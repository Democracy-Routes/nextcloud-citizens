# Running an assembly

This section is for the organizer: the person who plans an assembly, runs it from a laptop
and owns the report afterwards. It follows the order of a real event.

| Stage | Page |
|---|---|
| Understand the vocabulary | [Concepts](concepts.md) |
| Prepare: settings, consent, phones, rehearsal | [Before the day](before-the-day.md) |
| Run: recorders, Live tab, captions, replacements | [On the day](on-the-day.md) |
| Finish: review, report, publish, retention | [After the assembly](after.md) |
| Brief the person at each table | [Facilitator guide](facilitator.md) |
| Turn findings into a Polis conversation | [Polis consultation](polis.md) |
| Bring a session in, or rescue a failed table | [Recovery and import](recovery-import.md) |

!!! info "The honest headline"
    Audio is the primary record, and no software guarantees capture through a dead battery,
    a killed browser, a lost microphone or erased browser storage. The procedures in this
    section are arranged so that any of those happening is an annoyance, not a lost table.
    Read [Recording pipeline and reliability](../architecture/recording-pipeline.md) for what
    the software can and cannot survive.

Administration tasks (keys, providers, backups) are in [Administration](../admin/index.md).
Organizer routes exist for everything in the interface; they are in the
[API reference](../reference/api/index.md).
